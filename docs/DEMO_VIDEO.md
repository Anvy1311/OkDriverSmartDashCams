# 3–5 Minute Demonstration Runbook

The assignment requires a short screen recording of the actual working system, not a slide-only explanation. This runbook is designed for a 3–5 minute unlisted recording.

## Recording setup

- Run `docker compose up --build` or the local uvicorn command.
- Use a fresh `DATABASE_URL` or the seeded demo database.
- Keep the browser at `http://localhost:8000`.
- Record the browser, API response pane, and terminal only when needed.
- Do not show real credentials, real stream URLs, private keys, or personal data.

## Exact demo actions

1. Log in as the seeded admin.
2. Open **Camera registry** and select `C001`; show RTSP, location, storage, and health.
3. Select **GIS & movement** and filter markers by health.
4. Return to **Overview** and click **Simulate detection**.
5. Keep the page visible while the toast and alert counter update. The event is generated by the real backend simulator and persisted.
6. Open **Alert center**, acknowledge the new alert, then resolve it.
7. Trace `GJ01AB1234`; point out the sequence `C001 -> C003 -> C005` and the route line.
8. Open `/api/v1/system/readiness` and `/api/v1/dashboard/activity` to show persistence and operational health.
9. Briefly state that the same adapter contract accepts RTSP, ONVIF, vendor APIs, and WebRTC/HLS in production.

## Government-feed adaptation

When an approved government feed is supplied, keep the registry, analytics event schema, and alert workflow unchanged. Replace only the adapter configuration, add the feed’s legal access credentials to a vault, and record the supplied camera metadata through `POST /api/v1/cameras/bulk`. Confirm the designated vehicle identifier, run the trace, and capture the output report required by the hackathon.
